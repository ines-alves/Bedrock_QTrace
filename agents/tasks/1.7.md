## Plan before implementation

Implement `engine/aggregate.py` deduplication keyed by canonical identity,
parameters, asset type, and usage. Specific certificate/key resource identities
remain distinct; repeated algorithm usage merges evidence. Use content-derived
stable IDs, sorted unique occurrences/finding IDs, and bidirectional component
links. Avoid duplicate occurrences from multiple detectors at the same evidence.

Retain a private evidence index keyed by asset ID containing original findings,
confidence, offered/negotiated status, source/cloud exposure metadata, and warning
exclusions. Public CryptoAsset fields alone cannot reconstruct scoring. If any
finding is negotiated, the public summary marks that fact while the evidence index
still distinguishes offered-only occurrences. Test-only is true only if all
relevant code evidence is test-only. Do not merge conflicting parameter identities.
